# Electronic Mailbox & Document Flow System(G6)

## Project Vision
พัฒนาระบบรับและกระจายเอกสารอิเล็กทรอนิกส์ให้เป็นแพลตฟอร์มกลางที่ช่วยจัดการเอกสารตั้งแต่การรับ ลงทะเบียน จัดเก็บ และส่งต่ออย่างเป็นระบบ ผู้ใช้สามารถติดตามสถานะและตรวจสอบการดำเนินงานย้อนหลังได้ ช่วยลดปัญหาเอกสารสูญหาย งานล่าช้า และความไม่ชัดเจนในการส่งต่องานระหว่างฝ่าย

## Primary User
- เจ้าหน้าที่รับเอกสาร: รับและลงทะเบียนเอกสาร กำหนดข้อมูลเบื้องต้น และส่งต่อไปยังผู้เกี่ยวข้อง
- อาจารย์ / เจ้าหน้าที่: รับเอกสารหรือภารกิจที่เกี่ยวข้อง ดูรายละเอียด และดำเนินการตามสิทธิ์ที่ได้รับ
- ผู้รับผิดชอบเรื่อง: ติดตามและดำเนินการเอกสารที่ได้รับมอบหมาย พร้อมปรับสถานะหรือส่งต่อเมื่อจำเป็น
- ผู้ดูแลระบบ: จัดการผู้ใช้ สิทธิ์ ประเภทเอกสาร และข้อมูลพื้นฐานที่เกี่ยวข้องกับระบบ
- ผู้บริหาร: ดูภาพรวมสถานะเอกสาร งานค้าง ระยะเวลาดำเนินการ และข้อมูลสรุปเพื่อการติดตาม
  
## Problem
ปัจจุบันการรับและกระจายเอกสารภายในองค์กรมีเอกสารเข้ามาจากหลายช่องทาง เช่น Email, Line, ส่งโดยเจ้าหน้าที่สาขา และหน่วยงานภายนอก ทำให้เกิดปัญหาในการจัดการเอกสาร เช่น

- ข้อมูลเกี่ยวกับประเภทเอกสารและรายละเอียดที่ต้องเตรียมไม่ชัดเจน
- การส่งต่อเอกสารระหว่างผู้เกี่ยวข้องหลายฝ่ายอาจเกิดความล่าช้า
- ไม่สามารถตรวจสอบกระบวนการดำเนินงาน และ การตรวจสอบย้อนหลังของเอกสารได้อย่างชัดเจน
- เอกสารเกิดการสูญหาย


ระบบ Electronic Mailbox & Document Flow System จึงถูกพัฒนาเพื่อช่วยจัดการกระบวนการสำหรับลงทะเบียน ส่งต่อ และติดตามเอกสารอย่างเป็นระบบ โดยมีเป้าหมายเพื่อเพิ่มความถูกต้อง ความสามารถในการตรวจสอบย้อนหลัง (Traceability) และลดปัญหาเอกสารตกหล่น

## V1 Goal
V1 มุ่งเน้นการพัฒนา Information Service เพื่อให้ผู้ใช้งานสามารถเข้าถึงข้อมูลพื้นฐานเกี่ยวกับระบบรับและกระจายเอกสาร โดยยังไม่จำเป็นต้องเข้าสู่ระบบ

เป้าหมายของ V1 คือสร้างแหล่งข้อมูลที่ช่วยให้ผู้ใช้เข้าใจกระบวนการทำงานก่อนเริ่มใช้งานระบบจริง ได้แก่

ขอบเขตที่พัฒนาใน V1
- แสดงข้อมูลประเภทเอกสารที่ระบบรองรับ
1. เอกสารประชาสัมพันธ์ เช่น บริษัทด้านนอกฝากประชาสัมพันธ์การแข่ง hackathon
2. เอกสารขออนุมัติ เช่น ขอใช้สถานที่ห้องเรียนเพื่อทำกิจกรรมชมรม
3. เอกสารมอบหมายงาน เช่น มอบหมายให้คณะกรรมการไปลงพื้นที่เพื่อตรวจสอบ
4. เอกสารแจ้งเพื่อทราบ เช่น แจ้งว่าจะมีการพ่นไล่ยุงบริเวณอาคารที่กำหนด
5. เอกสารรอการตอบกลับ เช่น การเรียนเชิญบุคคลภายนอกมาเป็นวิทยากร
6. เอกสารแจ้งกำหนดการ/การนัดหมาย เช่น แจ้งว่ามีการนัดหมายให้ไปที่นี่เวลานี้
7. เอกสารรายงานผล เช่น รายงานผลการปรับรูปแบบการสอน

- แสดงช่องทางการรับเอกสาร
  - Email
  - กระดาษ

- แสดงขั้นตอนการดำเนินงานของเอกสาร (Document Workflow)

    เจ้าหน้าที่รับเอกสาร --> ตรวจสอบข้อมูล --> ส่งต่อผู้เกี่ยวข้อง --> ดำเนินการ --> เสร็จสิ้น

- แสดงข้อมูลที่จำเป็นสำหรับการส่งเอกสาร
1. ประเภทเอกสาร — เช่น หนังสือราชการ, บันทึกข้อความ, คำร้อง, แบบฟอร์ม
2. ช่องทางการส่ง — เช่น Email หรือ ส่งเอกสารกระดาษ
3. ไฟล์ที่ต้องแนบ — เช่น PDF หรือรูปแบบไฟล์ที่ระบบรองรับ
4. ข้อมูลผู้ส่ง — ชื่อ, หน่วยงาน, ช่องทางติดต่อ
5. ข้อมูลผู้รับ — สาขา / หน่วยงาน / บุคคลที่ต้องการส่งถึง
6. ข้อมูลประกอบเอกสาร — เช่น เลขที่หนังสือ, วันที่ออกเอกสาร, เรื่อง, ประเภทเอกสาร
7. กำหนดการหรือ Deadline — ถ้าเอกสารมีวันที่ต้องดำเนินการ
8. ข้อกำหนดเพิ่มเติม — เช่น ต้องลงนาม, ต้องแนบเอกสารประกอบ เป็นต้น

## V1 In scope
- แสดงข้อมูลพื้นฐานของระบบโดยไม่ต้อง Login
- แสดงประเภทเอกสารที่ระบบรองรับ
- แสดงช่องทางการรับเอกสาร
- แสดงขั้นตอนการดำเนินงานของเอกสาร
- แสดงข้อมูลที่จำเป็นสำหรับการส่งเอกสาร
- ใช้ Mock Data สำหรับทดสอบการแสดงผลใน V1
- ออกแบบและจัดทำ V1 Architecture Documentation
  
## V1 Out of scope
- การ Login / Authentication
- การ Upload และส่งเอกสารจริง
- การลงทะเบียนเอกสารจริง
- การส่งต่อเอกสารจริง
- การติดตามสถานะเอกสารแบบ Real-time
- การแจ้งเตือนผู้เกี่ยวข้อง
- การค้นหาเอกสารในระบบ
- การจัดเก็บเอกสารจริงบนระบบ
- การจัดการสิทธิ์ผู้ใช้งาน
- การแก้ไข/อนุมัติเอกสาร

## External actors / systems
### External Actors
- ผู้ส่งเอกสาร — เข้ามาดูข้อมูลประเภทเอกสาร ช่องทางการรับ และข้อมูลที่ต้องเตรียมก่อนส่งเอกสาร
- เจ้าหน้าที่ — ให้ข้อมูลเกี่ยวกับประเภทเอกสาร ช่องทางการรับ และ Workflow ที่ใช้ในหน่วยงาน
### External System
- Amazon S3 (ใช้จัดเก็บข้อมูลสำหรับ Information Service ของ V1)
